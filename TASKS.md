# Open Tasks

## Improve audio-to-note conversion with AI post-processing

**Where:** `cloudfare_worker/worker.js`, `transcribeWithCfAi()` / `createTodoistTask()`

**Current behavior:** The worker transcribes the uploaded audio with
`@cf/openai/whisper` (`transcribeWithCfAi`) and passes the raw transcription
straight into the Todoist task (`createTodoistTask`) as both `content`
(title) and `description`, with no cleanup or enrichment step in between.

**Requested improvements:**

1. **AI transcription cleanup step (language-aware).** After
   `transcribeWithCfAi` returns the raw Whisper output, add a further AI step
   that adjusts/cleans up the transcription — fixing grammar, punctuation,
   filler words/disfluencies, obvious mis-transcriptions — using the
   `language` value already sent by the watch (`dudu_language` setting,
   forwarded in the upload body, see `zepp_app/app-side/index.js`) so the
   correction is tuned to the chosen language rather than assuming English.

2. **AI description enrichment step.** Before calling `createTodoistTask`,
   run the (cleaned-up) transcription through a second AI step that expands
   it into a more detailed Todoist task description — adding relevant
   context/structure to the raw note. If the transcription doesn't contain
   enough information to produce a useful description, this step should
   generate clarifying questions and include them in the Todoist task
   description instead of (or alongside) a thin description, so the user is
   prompted to fill in the gaps when they open the task.

**Open questions to resolve during implementation:**
- Which AI provider/model handles these two steps — reuse Cloudflare
  Workers AI (already available via `env.AI`), or call an external LLM API?
- Should the two steps be separate calls or a single combined prompt?
- Should the task `content` (title) stay as a short summary of the raw
  transcription, or also be regenerated by AI?
- Failure handling: if the cleanup/enrichment step fails or times out,
  should the worker fall back to the raw transcription (as it does today)
  rather than failing the whole upload?
