# Open Tasks

## Improve audio-to-note conversion with AI post-processing

**Where:** `cloudfare_worker/worker.js`, `transcribeWithCfAi()` / `createTodoistTask()`

**Current behavior:** The worker transcribes the uploaded audio with
`@cf/openai/whisper` (`transcribeWithCfAi`) and passes the raw transcription
straight into the Todoist task (`createTodoistTask`) as both `content`
(title) and `description`, with no cleanup or enrichment step in between.

**Requested improvements:**

1. **AI transcription cleanup step (language-aware).** After
   `transcribeWithCfAi` returns the raw Whisper output, add a further AI step
   that adjusts/cleans up the transcription — fixing grammar, punctuation,
   filler words/disfluencies, obvious mis-transcriptions — using the
   `language` value already sent by the watch (`dudu_language` setting,
   forwarded in the upload body, see `zepp_app/app-side/index.js`) so the
   correction is tuned to the chosen language rather than assuming English.

2. **AI description enrichment step.** Before calling `createTodoistTask`,
   run the (cleaned-up) transcription through a second AI step that expands
   it into a more detailed Todoist task description — adding relevant
   context/structure to the raw note. If the transcription doesn't contain
   enough information to produce a useful description, this step should
   generate clarifying questions and include them in the Todoist task
   description instead of (or alongside) a thin description, so the user is
   prompted to fill in the gaps when they open the task.

**Implementation approach decided:** single combined AI call (one prompt
doing both language-aware cleanup and description enrichment/clarifying
questions), not two separate steps — simpler, one round-trip per upload.

**Model options (decision support):**

| Option | Cost | Notes |
|---|---|---|
| Cloudflare Workers AI (`env.AI`, already bound) — small model, e.g. `@cf/meta/llama-3.1-8b-instruct-fast` or `@cf/openai/gpt-oss-20b` | **Free** up to 10,000 Neurons/day (resets 00:00 UTC, no card required); $0.011/1,000 Neurons above that (Workers Paid plan) | Whisper transcription already draws from this same daily pool. Neuron cost per call varies a lot by model size — a 70B/120B model burns the free allowance much faster than an 8B/20B one. At personal-use volume, a small model would very likely stay free indefinitely. Weaker instruction-following for a two-part task (correction + conditional clarifying questions) than a hosted frontier model. No new secret needed. |
| Anthropic Claude via raw `fetch()` to `/v1/messages` (consistent with the existing raw-`fetch()` Todoist call — no SDK needed in the Workers runtime) | No free tier; pay per token from the first call. `claude-haiku-4-5`: $1/$5 per MTok (in/out) — cheapest, likely a few cents/month at this app's volume. `claude-sonnet-5`: $3/$15 per MTok (intro $2/$10) if Haiku's quality isn't sufficient. `claude-opus-5`: $5/$25 per MTok — likely overkill here. | Needs a new `ANTHROPIC_API_KEY` secret (`wrangler secret put ANTHROPIC_API_KEY`). Noticeably more reliable at the two-part task than a small Workers AI model. |
| OpenAI (e.g. `gpt-4.1-mini`) | Pay per token | `worker.js`'s header comment already references `OPENAI_API_KEY` as a secret, but no code currently uses it — the actual transcription call goes through the Cloudflare Workers AI binding (`@cf/openai/whisper`), not the real OpenAI API. Would need to actually wire up this secret if chosen. |

**Recommendation:** start with Workers AI + a small model (free, no new
secret) since this is a personal-use app; fall back to Claude Haiku 4.5 via
raw `fetch()` if the small model's output quality (especially the
clarifying-questions behavior) isn't good enough in practice.

**Other open questions to resolve during implementation:**
- Should the task `content` (title) stay as a short summary of the raw
  transcription, or also be regenerated by AI?
- Failure handling: if the cleanup/enrichment step fails or times out,
  should the worker fall back to the raw transcription (as it does today)
  rather than failing the whole upload?
